Thier Décor — ملاحظات أمنية وتشغيلية (اقرأ قبل النشر)

مهم: ملفات الواجهة وحدها لا تستطيع تأمين قاعدة البيانات. مفتاح Supabase publishable ليس سراً، وحماية لوحة المدير عبر Firebase في المتصفح لا تجعل طلبات Supabase موثوقة تلقائياً.

لا تشغّل سياسات RLS عامة عشوائياً: قد تمنع المتجر من العمل أو تكشف البيانات. المشروع الحالي يستخدم حسابات زبائن مخصصة في جدول customers، ولا توجد في هذه الحزمة آلية موثوقة تربط Firebase JWT بسياسات Supabase.

قبل النشر التجاري يجب تنفيذ ترحيل مصادقة الزبائن إلى Supabase Auth أو نقل العمليات الحساسة إلى Edge Functions تتحقق من Firebase JWT، ثم تفعيل RLS بسياسات متوافقة مع هوية موثقة. يجب كذلك نقل حساب إجمالي الطلب والخصم والمخزون إلى معاملة/دالة خادم واحدة. لا تضع service_role key في ملفات الموقع.

SQL المرفق:
- Thier_Decor_Packs_Promos_Migration.sql: أعمدة الحزم/العروض.
- Thier_Decor_Packs_Promos_PhoneBound_Coupons_Migration.sql: تتبع استخدام الكوبونات ودوال التحقق والاستهلاك.
- analytics_visitors.sql: دوال عدّ الزيارات.
راجع أسماء الأعمدة وأنواعها في مشروعك قبل تشغيلها، وخذ نسخة احتياطية أولاً.

الاختبارات الآلية التي أُجريت: فحص صياغة JavaScript فقط. لم يُجر اختبار متصفح أو اتصال حي بقاعدة بيانات Supabase، لذلك لا تعتبر هذه الحزمة اعتماداً أمنياً أو ضماناً أن كل السياسات/الميزات تعمل على قاعدة بياناتك.
